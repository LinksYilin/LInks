# 训练数据氢不一致问题（本轮新发现）

> 发现时间：本轮 WS1 准备阶段（给 EGNN 补 3D 坐标时）
> 严重度：**高** —— 影响全部 ΔΔG 预测结果
> 状态：**已修复**，需重训全部模型

---

## 一、问题

给 EGNN 补坐标时，我发现 `contact_graphs_megascale_sc`（训练图的 MegaScale 半）与
新建的排氢版 `_centroid` **边集不同**。逐层追查后确认：

| 数据集 | 样本 | 质心定义 | 判定依据 |
|---|---|---|---|
| **megascale_sc（训练，MegaScale 半）** | **239 / 239** | **含氢** ❌ | 1A32 边数 206 = 含氢版本 |
| thermomutdb_sc（训练，另一半） | 324 / 324 | 排氢 ✅ | 与新定义完全一致 |
| s669_sc（测试） | 88 / 88 | 排氢 ✅ | 与新定义完全一致 |
| ssym_sc（测试） | 15 / 15 | 排氢 ✅ | 与新定义完全一致 |

**验证方式**：对 1A32 分别用"含氢质心"与"排氢质心"构建接触图，
含氢 = 206 边、排氢 = 192 边，`_sc` 与含氢版本**完全吻合**（10/10 抽查，全量 239/239）。

**原因**：AlphaFold 结构**确实含氢**（1A32：1095 个原子中 566 个是氢）。
早前修复 `build_contact_graph.get_cb_coord` 排除氢之后，
s669 / ssym / thermomutdb 都重建了，**但 megascale 没有真正重建**。

> ⚠️ 更正记录：此前会话曾声称"megascale 已重建为排氢 239 个"——
> **该说法不成立**，实际目录内容始终是含氢版本。本次审计推翻了它。

---

## 二、后果

1. **训练/测试表示不一致**：模型在"含氢质心"上训练，却在"排氢质心"上评估。
2. 训练集内部也不一致：MegaScale 半（含氢）与 ThermoMutDB 半（排氢）用了**两种不同表示**。
3. 因此**论文全部预测数字（r = 0.32–0.41 等）都建立在有缺陷的训练数据上**。

---

## 三、修复

| 步骤 | 动作 |
|---|---|
| 1 | 用排氢版（`contact_graphs_megascale_centroid`，已验证 239/239 排氢 + 含 coords）替换 `_sc` |
| 2 | 旧（含氢）目录归档为 `contact_graphs_megascale_sc_Hincluded_bug`（**保留，不删除**） |
| 3 | 另一份旧备份保留为 `contact_graphs_megascale_sc_nocoords_backup` |
| 4 | 验证：239/239 与排氢版**逐元素一致**，且全部含 coords |

**修复后状态**：

```
contact_graphs_megascale_sc                 239 图, 排氢, 含 coords   ← 正确
contact_graphs_megascale_centroid           239 图, 排氢, 含 coords   ← 同一内容
contact_graphs_megascale_sc_Hincluded_bug   239 图, 含氢, 无 coords   ← 审计痕迹
contact_graphs_megascale_sc_nocoords_backup 239 图, 含氢, 无 coords   ← 审计痕迹
```

## 四、对论文的影响

**必须重训全部模型并更新所有预测数字。** 这正好与本轮 WS1（能力阶梯）合并进行：

- 训练数据修复 → 重训能力阶梯（5–7 档骨架 × 4 定义 × 多种子）
- 全部预测结果（Table 1、Figure 1、配对检验、阈值敏感性、表示比较）**数字都会变化**
- 接触编辑分析（编辑率 0%→90.7%、局部性 4.03 Å）**不受影响**——
  那部分用的是 s669 的 WT/MT 图，本来就是排氢的

**对论文叙事是加强而非削弱**：这是一次真实的、可报告的数据质量控制发现，
与论文"严谨受控基准"的定位一致。
